AI面试常见代码题

Last updated on October 11, 2026 pm

本文整理大模型算法面试中常见的 PyTorch 手写题。每道题都是独立实现；重点不仅是背出 API，还要能解释 Tensor Shape、Mask 语义和公式与代码的对应关系。

0. 统一约定

本文主要使用以下符号：

  • BBB：Batch Size；
  • TTT：Sequence Length；
  • DDD：Hidden Size；
  • HHH：Attention Head 数量；
  • Dh=D/HD_h=D/HDh​=D/H：每个 Attention Head 的维度；
  • VVV：Vocabulary Size；
  • mask=True/1：该位置有效；
  • Logits 表示 Softmax 前的分数，Log Probability 表示 log_softmax 后的值。

面试手写时应优先保证：

  1. 输入、输出 Shape 正确；
  2. Mask 的广播方向和语义正确；
  3. Padding 不进入 Loss；
  4. 数值计算使用 log_softmax、logsigmoid 等稳定实现；
  5. 需要固定的 Target、Old Log Probability 和 Advantage 使用 detach()。

S 级：需要熟练手写

1. Multi-head Attention

目标

输入：

X∈RB×T×D.X\in\mathbb R^{B\times T\times D}. X∈RB×T×D.

先投影得到 Q,K,VQ,K,VQ,K,V，再拆成 HHH 个 Heads：

Q,K,V∈RB×H×T×Dh.Q,K,V\in\mathbb R^{B\times H\times T\times D_h}. Q,K,V∈RB×H×T×Dh​.

Scaled Dot-product Attention 为：

Attention⁡(Q,K,V)=softmax⁡(QKTDh+M)V.\operatorname{Attention}(Q,K,V) = \operatorname{softmax} \left( \frac{QK^T}{\sqrt{D_h}}+M \right)V. Attention(Q,K,V)=softmax(Dh​​QKT​+M)V.

其中 MMM 是调用方直接传入的通用 Attention Mask，Shape 规定为 (B,T,T)(B,T,T)(B,T,T)，可以是 Causal Mask、Padding Mask 或二者组合后的结果。本文约定 True 表示允许关注，False 表示屏蔽。

PyTorch 实现

例如，Decoder Self-Attention 的 Causal Mask 可以由调用方构造：

最容易写错的是：

  • K 应转置最后两个维度，而不是 Head 与 Sequence 维；
  • Attention Score 的 Shape 是 (B,H,T,T)(B,H,T,T)(B,H,T,T)；
  • (B,T,T)(B,T,T)(B,T,T) 的 Mask 需要增加 Head Dimension 后再广播；
  • masked_fill 必须发生在 Softmax 之前。

2. PPO Clipped Loss

目标

已知每个 Token 的：

  • old_log_probs：生成轨迹的 Old Policy Log Probability；
  • new_log_probs：Current Policy 重新计算的 Log Probability；
  • advantages：固定的 Advantage。

概率比为：

ρt=exp⁡(ℓtnew−ℓtold).\rho_t = \exp \left( \ell_t^{\mathrm{new}}-\ell_t^{\mathrm{old}} \right). ρt​=exp(ℓtnew​−ℓtold​).

PPO Clipped Objective 为：

Jclip=Et[min⁡(ρtAt,clip⁡(ρt,1−ϵ,1+ϵ)At)].J_{\mathrm{clip}} = \mathbb E_t \left[ \min \left( \rho_tA_t, \operatorname{clip}(\rho_t,1-\epsilon,1+\epsilon)A_t \right) \right]. Jclip​=Et​[min(ρt​At​,clip(ρt​,1−ϵ,1+ϵ)At​)].

训练代码通常最小化其相反数。

PyTorch 实现

torch.minimum 不能简单替换成“始终使用裁剪后的 Ratio”。PPO 只阻止沿正确方向获得过大的额外收益；如果 Policy 向错误方向移动，仍要保留未裁剪分支提供纠正梯度。

面试手写通常默认输入位置全部有效。实际处理变长 Response 时，还需要用 Response Mask 排除 Padding Token。

3. GRPO Loss

目标

假设一个 Batch 有 BBB 个 Prompt，每个 Prompt 生成 GGG 条 Response：

R∈RB×G.R\in\mathbb R^{B\times G}. R∈RB×G.

GRPO 使用同组 Reward 的均值和标准差构造 Advantage：

Ab,g=Rb,g−μbσb+ε.A_{b,g} = \frac{ R_{b,g}-\mu_b }{ \sigma_b+\varepsilon }. Ab,g​=σb​+εRb,g​−μb​​.

一个 Response 的 Advantage 会广播到该 Response 的所有 Tokens，再结合 Importance Ratio 和 PPO Clipping。

PyTorch 实现

若一组 Response 全部得到相同 Reward，则分子为 000，该组 Advantage 为 000，不会产生 Actor Gradient。unbiased=False 使用总体标准差，也避免 Group Size 较小时额外的 Bessel Correction。

实际处理变长 Response 时，需要在计算平均值时用 Response Mask 排除 Padding Token。

4. GAE

目标

TD Residual：

δt=rt+γ(1−dt)V(st+1)−V(st),\delta_t = r_t+\gamma(1-d_t)V(s_{t+1})-V(s_t), δt​=rt​+γ(1−dt​)V(st+1​)−V(st​),

GAE 从后向前递推：

At=δt+γλ(1−dt)At+1.A_t = \delta_t +\gamma\lambda(1-d_t)A_{t+1}. At​=δt​+γλ(1−dt​)At+1​.

其中 dt=1d_t=1dt​=1 表示执行第 ttt 步动作后 Episode 结束。

PyTorch 实现

如果轨迹因为真正到达 EOS 而结束，应令最后有效位置的 done=1，此时不再 Bootstrap；如果只是因为固定长度切断但环境并未终止，则可以令 done=0，并通过 last_values Bootstrap。

5. DPO Loss

目标

每条偏好数据包含：

(x,yw,yl),(x,y_w,y_l), (x,yw​,yl​),

其中 ywy_wyw​ 是 Chosen Response，yly_lyl​ 是 Rejected Response。定义 Policy 与 Reference Model 对整条 Response 的 Sequence Log Probability：

log⁡π(y∣x)=∑t=1Tlog⁡π(yt∣x,y<t).\log\pi(y\mid x) = \sum_{t=1}^{T} \log\pi(y_t\mid x,y_{<t}). logπ(y∣x)=t=1∑T​logπ(yt​∣x,y<t​).

DPO Logit 为：

z=β[log⁡πθ(yw∣x)πref(yw∣x)−log⁡πθ(yl∣x)πref(yl∣x)].z = \beta \left[ \log\frac{\pi_\theta(y_w\mid x)}{\pi_{\mathrm{ref}}(y_w\mid x)} - \log\frac{\pi_\theta(y_l\mid x)}{\pi_{\mathrm{ref}}(y_l\mid x)} \right]. z=β[logπref​(yw​∣x)πθ​(yw​∣x)​−logπref​(yl​∣x)πθ​(yl​∣x)​].

PyTorch 实现

DPO 不要求 Reward Model、Critic 或在线 Rollout，但需要固定的 Chosen/Rejected 偏好对以及 Reference Model。四个输入必须是 Response Tokens 的 Log Probability 之和，不能把 Prompt Tokens 也计入。

A 级：常见基础组件

6. RMSNorm

目标

输入：

X∈RB×T×D.X\in\mathbb R^{B\times T\times D}. X∈RB×T×D.

RMSNorm 固定 b,tb,tb,t，只沿 Hidden Dimension DDD 计算：

RMS⁡(Xb,t,:)=1D∑j=1DXb,t,j2+ϵ.\operatorname{RMS}(X_{b,t,:}) = \sqrt{ \frac{1}{D}\sum_{j=1}^{D}X_{b,t,j}^2+\epsilon }. RMS(Xb,t,:​)=D1​j=1∑D​Xb,t,j2​+ϵ​.

与 LayerNorm 不同，RMSNorm 不减均值，通常也不使用 Bias：

Yb,t,j=wjXb,t,jRMS⁡(Xb,t,:).Y_{b,t,j} = w_j \frac{ X_{b,t,j} }{ \operatorname{RMS}(X_{b,t,:}) }. Yb,t,j​=wj​RMS(Xb,t,:​)Xb,t,j​​.

PyTorch 实现

可学习参数只有 weight，Shape 为 (D,)(D,)(D,)，它会在前面的所有维度广播。

7. RoPE

目标

RoPE 将 Head Dimension 中相邻的两个维度组成二维向量。第 iii 对维度的角频率为：

ωi=base−2iDh,\omega_i = \mathrm{base}^{-\frac{2i}{D_h}}, ωi​=base−Dh​2i​,

位置 ttt 的旋转角度为：

θt,i=tωi.\theta_{t,i}=t\omega_i. θt,i​=tωi​.

对每一对元素 (x2i,x2i+1)(x_{2i},x_{2i+1})(x2i​,x2i+1​) 执行：

x2i′=x2icos⁡θ−x2i+1sin⁡θ,x2i+1′=x2isin⁡θ+x2i+1cos⁡θ.\begin{aligned} x'_{2i} &= x_{2i}\cos\theta-x_{2i+1}\sin\theta,\\ x'_{2i+1} &= x_{2i}\sin\theta+x_{2i+1}\cos\theta. \end{aligned} x2i′​x2i+1′​​=x2i​cosθ−x2i+1​sinθ,=x2i​sinθ+x2i+1​cosθ.​

RoPE 只应用于 Query 和 Key，不应用于 Value。

PyTorch 实现

若使用 KV Cache，历史 Key 在写入 Cache 前就应应用其对应位置的 RoPE；新 Token 的 Query 和 Key 只使用新位置的角度。

8. KV Cache Attention

目标

自回归生成第 ttt 个 Token 时，历史 Tokens 的 Key 和 Value 不会变化。KV Cache 保存：

K≤t,V≤t∈RB×H×Tcache×Dh.K_{\le t},V_{\le t} \in \mathbb R^{B\times H\times T_{\mathrm{cache}}\times D_h}. K≤t​,V≤t​∈RB×H×Tcache​×Dh​.

每一步只计算新 Token 的 Qt,Kt,VtQ_t,K_t,V_tQt​,Kt​,Vt​，把 Kt,VtK_t,V_tKt​,Vt​ 追加到 Cache，然后让 QtQ_tQt​ 关注全部 Cached Keys。

PyTorch 实现

该实现同步维护 cache["mask"]，因此不同样本的 Prompt 长度不同时也不会关注 Padding KV。代码用 torch.cat 强调逻辑；生产环境会预分配最大 Cache，再按位置原地写入，避免每一步重新分配和复制历史 KV。

9. SFT Cross-entropy Loss

目标

Causal LM 在位置 ttt 的 Logits 用来预测位置 t+1t+1t+1 的 Token，因此需要 Shift：

如果只希望对 Assistant Response 做 SFT，还要同时满足：

  • 目标位置不是 Padding；
  • 目标位置属于 Response。

PyTorch 实现

response_mask 标记的是 Token 自身是否属于 Response，所以 Shift 后应使用 response_mask[:, 1:]。如果把 Prompt 也设为有效，就会变成对整段对话计算 Language Modeling Loss。

10. 从 Logits 提取 Token Log Probability

目标

模型输出：

Z∈RB×L×V.Z\in\mathbb R^{B\times L\times V}. Z∈RB×L×V.

先在 Vocabulary Dimension 做：

log⁡P=logsoftmax⁡(Z,dim⁡=−1),\log P=\operatorname{logsoftmax}(Z,\dim=-1), logP=logsoftmax(Z,dim=−1),

再使用真实 Token ID 从 VVV 个候选中 gather 对应位置。

PyTorch 实现

若只需要 Response Token 的 Log Probability，再使用 Shift 后的 Response Mask：

不能先 softmax 再 log，log_softmax 的数值稳定性更好。

11. KL Divergence 与 Entropy

目标

给定 Policy Distribution ppp 和 Reference Distribution qqq：

DKL(p∥q)=∑ap(a)[log⁡p(a)−log⁡q(a)].D_{\mathrm{KL}}(p\Vert q) = \sum_a p(a) \left[ \log p(a)-\log q(a) \right]. DKL​(p∥q)=a∑​p(a)[logp(a)−logq(a)].

Policy Entropy 为：

H(p)=−∑ap(a)log⁡p(a).H(p) = -\sum_a p(a)\log p(a). H(p)=−a∑​p(a)logp(a).

两者都在 Vocabulary Dimension 上求和。

PyTorch 实现

第一种实现需要保留完整 Vocabulary Distribution，计算精确但显存较高；大模型 RL 中经常只保存已采样 Token 的 Log Probability，使用第二种 Sample-based Estimator。此时必须说明 Token 的采样分布：若数据来自不同的 Old Policy，就不能直接把未加权的样本均值称为 Current Policy 对 Reference Policy 的无偏 KL 估计。

B 级：进阶结构与工程题

12. GQA 与 MQA

目标

MHA 中 Query、Key、Value 的 Head 数相同：

Hq=Hkv.H_q=H_{kv}. Hq​=Hkv​.

GQA 让多个 Query Heads 共享一组 Key/Value Head：

1<Hkv<Hq.1<H_{kv}<H_q. 1<Hkv​<Hq​.

MQA 是 GQA 的特殊情况：

Hkv=1.H_{kv}=1. Hkv​=1.

要求 HqH_qHq​ 能被 HkvH_{kv}Hkv​ 整除。实现时将每个 KV Head 重复：

nrep=HqHkvn_{\mathrm{rep}}=\frac{H_q}{H_{kv}} nrep​=Hkv​Hq​​

次，使其与 Query Heads 对齐。

PyTorch 实现

减少 HkvH_{kv}Hkv​ 不会减少 Query Heads，因此仍能保留多组 Query 表示；它主要减少 K/V Projection 参数和 KV Cache 大小。

13. Top-k 与 Top-p Sampling

目标

  • Top-k：只保留 Logits 最大的 kkk 个 Tokens；
  • Top-p：保留按概率从高到低排序后，累计概率刚达到阈值 ppp 的最小 Token 集合；
  • Temperature：使用 z/τz/\tauz/τ 调整分布尖锐程度。

过滤后重新 Softmax，再使用 torch.multinomial 采样。

PyTorch 实现

Top-p 中必须保留“第一个越过阈值”的 Token，否则保留集合的累计概率可能小于指定的 ppp。

14. LoRA Linear

目标

冻结原始权重：

W0∈RDout×Din,W_0\in\mathbb R^{D_{\mathrm{out}}\times D_{\mathrm{in}}}, W0​∈RDout​×Din​,

只训练两个低秩矩阵：

A∈Rr×Din,B∈RDout×r.A\in\mathbb R^{r\times D_{\mathrm{in}}}, \qquad B\in\mathbb R^{D_{\mathrm{out}}\times r}. A∈Rr×Din​,B∈RDout​×r.

前向传播为：

y=W0x+αrBAx.y = W_0x + \frac{\alpha}{r}BAx. y=W0​x+rα​BAx.

PyTorch 实现

lora_b 初始化为零非常重要：训练开始时模块行为与原始 Linear 完全一致，但 lora_b 在第一步可以获得梯度；之后 lora_a 也会逐渐获得非零梯度。

15. FlashAttention 原理伪代码

目标

普通 Attention 会显式构造：

S=QKT∈RB×H×T×T,S=QK^T\in\mathbb R^{B\times H\times T\times T}, S=QKT∈RB×H×T×T,

其显存复杂度为 O(T2)O(T^2)O(T2)。FlashAttention 将 Query 和 Key/Value 切成 Blocks，并使用 Online Softmax 维护：

  • 当前最大值 mmm；
  • Softmax 分母 lll；
  • 未归一化输出累积量 OOO。

这样不需要把完整的 T×TT\times TT×T Attention Matrix 写回显存。

PyTorch 原理实现

真正的 FlashAttention 会将 Block 计算融合进 CUDA/Triton Kernel，并实现对应的分块反向传播。面试重点是解释 Online Softmax 如何在最大值变化时重新缩放旧的分母与输出累积量。

16. Transformer Block

目标

现代 Decoder-only LLM 通常使用 Pre-Norm：

X1=X+Attention⁡(RMSNorm⁡(X)),X_1 = X+\operatorname{Attention}(\operatorname{RMSNorm}(X)), X1​=X+Attention(RMSNorm(X)),

Xout=X1+SwiGLU⁡(RMSNorm⁡(X1)).X_{\mathrm{out}} = X_1+\operatorname{SwiGLU}(\operatorname{RMSNorm}(X_1)). Xout​=X1​+SwiGLU(RMSNorm(X1​)).

SwiGLU 为：

SwiGLU⁡(x)=Wdown[SiLU⁡(Wgatex)⊙(Wupx)].\operatorname{SwiGLU}(x) = W_{\mathrm{down}} \left[ \operatorname{SiLU}(W_{\mathrm{gate}}x) \odot (W_{\mathrm{up}}x) \right]. SwiGLU(x)=Wdown​[SiLU(Wgate​x)⊙(Wup​x)].

PyTorch 实现

完整现代 LLM 还会加入 RoPE、GQA、KV Cache、FlashAttention 和 Tensor Parallel；面试手写 Block 时，先保证 Pre-Norm、Residual 和 SwiGLU 的数据流正确。

17. RL Rollout Masking

目标

同一个 Batch 中的 Responses 长度不同，需要 Padding 到统一长度：

Response Mask 应包含真实 Tokens 和第一个 EOS，但排除 EOS 后的 Padding。Reward、Log Probability、Advantage 和 PPO Loss 都必须使用同一套有效位置定义。

PyTorch 实现

若 pad_token_id == eos_token_id，不能简单使用 responses != pad_token_id 构造 Mask，否则真正的 EOS 也会被删除。最稳妥的方式是直接使用 Rollout Engine 返回的生成长度；没有长度时，再根据第一个 EOS 推断。

还要区分 terminated 与 truncated：生成 EOS 表示 Episode 真正结束，应在最后有效位置设置 done=True；达到最大长度但没有 EOS 只是截断，应保持 done=False，并在 GAE 中使用截断位置之后的 last_values 做 Bootstrap。

18. 面试前的检查清单

写完代码后，至少检查：

  1. Attention 的 Score Shape 是否为 (B,H,Tq,Tk)(B,H,T_q,T_k)(B,H,Tq​,Tk​)；
  2. Causal Mask 和 Padding Mask 是否在 Softmax 前生效；
  3. Causal LM 的 Logits 与 Labels 是否正确 Shift；
  4. Token ID 是否通过 gather 从 Vocabulary Dimension 取概率；
  5. Padding、Prompt 和 EOS 是否按题意进入 Loss；
  6. Old Log Probability、Advantage、Return、Reference Log Probability 是否停止梯度；
  7. 所有除法分母是否处理空 Mask 或零方差；
  8. BF16/FP16 下归一化、Softmax 累积是否需要转 FP32；
  9. .transpose() 后使用 .view() 前是否调用 .contiguous()；
  10. 返回的是要最大化的 Objective，还是供 Optimizer 最小化的 Loss。

真正的面试重点不是逐字背代码，而是能够根据公式恢复实现，并在写代码的同时说清楚每个 Tensor 的 Shape 和 Mask 语义。
