一、面试手写 Decoder-only Transformer

大模型算法面试中，Transformer 手写题通常不是要求从头复现完整的 LLaMA，而是检查是否真正理解几个核心组件：

  1. Scaled Dot-product Attention 与 Causal Mask；
  2. Multi-head Attention 中的 Shape 变换；
  3. RoPE；
  4. RMSNorm；
  5. SwiGLU；
  6. Pre-Norm、Residual Connection 与完整 Transformer Block；
  7. Next-token Prediction 的 Shift。

下面使用 PyTorch 分组件实现一个最小 Decoder-only Transformer。代码重点是结构与 Tensor Shape，不包含 FlashAttention、Tensor Parallel、KV Cache 和混合精度等工程优化。

1.1 RMSNorm

设 RMSNorm 的输入为：

X∈RB×T×D,X\in\mathbb R^{B\times T\times D}, X∈RB×T×D,

其中：

  • BBB：Batch Size；
  • TTT：Sequence Length；
  • DDD：Hidden Size；
  • Xb,t,:∈RDX_{b,t,:}\in\mathbb R^DXb,t,:​∈RD：第 bbb 个样本中第 ttt 个 Token 的 Hidden Vector。

RMSNorm 对每个 Token 的 Hidden Dimension 单独计算均方根。也就是说，固定 b,tb,tb,t，只在最后一维 j=1,…,Dj=1,\ldots,Dj=1,…,D 上求均值：

RMS⁡(Xb,t,:)=1D∑j=1DXb,t,j2+ϵ.\operatorname{RMS}(X_{b,t,:}) = \sqrt{ \frac{1}{D} \sum_{j=1}^{D}X_{b,t,j}^{2} +\epsilon }. RMS(Xb,t,:​)=D1​j=1∑D​Xb,t,j2​+ϵ​.

然后对该 Token 的每个 Hidden Dimension 做缩放：

Yb,t,j=wjXb,t,jRMS⁡(Xb,t,:),Y_{b,t,j} = w_j \frac{X_{b,t,j}} {\operatorname{RMS}(X_{b,t,:})}, Yb,t,j​=wj​RMS(Xb,t,:​)Xb,t,j​​,

其中：

  • w∈RDw\in\mathbb R^Dw∈RD：可学习的缩放参数；
  • wjw_jwj​：第 jjj 个 Hidden Dimension 对应的参数；
  • ϵ\epsilonϵ：防止分母为零的常数；
  • Y∈RB×T×DY\in\mathbb R^{B\times T\times D}Y∈RB×T×D：RMSNorm 的输出。

因此 RMSNorm：

  • 不在 Batch Dimension BBB 上统计；
  • 不在 Sequence Dimension TTT 上统计；
  • 只在每个 Token 内部的 Hidden Dimension DDD 上统计；
  • 输入和输出 Shape 都是 (B,T,D)(B,T,D)(B,T,D)。

与 LayerNorm 相比，RMSNorm 不计算并减去均值，只根据均方根控制向量尺度，因此计算更简单。

1.2 RoPE

Multi-head Attention 拆分 Head 后，Query 和 Key 的 Shape 为：

Q,K∈RB×H×T×Dh,Q,K\in \mathbb R^{B\times H\times T\times D_h}, Q,K∈RB×H×T×Dh​,

其中：

  • BBB：Batch Size；
  • HHH：Attention Head 数量；
  • TTT：Sequence Length；
  • DhD_hDh​：每个 Head 的维度，要求是偶数；
  • Qb,h,m,:Q_{b,h,m,:}Qb,h,m,:​：第 bbb 个样本、第 hhh 个 Head 在位置 mmm 的 Query；
  • Kb,h,n,:K_{b,h,n,:}Kb,h,n,:​：第 bbb 个样本、第 hhh 个 Head 在位置 nnn 的 Key。

RoPE 不把 Position Embedding 加到 Token Hidden State 上，而是根据位置分别旋转 QQQ 和 KKK。它把 Head Dimension 中相邻的两个维度看作一个二维向量：

[Qm,2iQm,2i+1],i=0,1,…,Dh2−1.\begin{bmatrix} Q_{m,2i}\\ Q_{m,2i+1} \end{bmatrix}, \qquad i=0,1,\ldots,\frac{D_h}{2}-1. [Qm,2i​Qm,2i+1​​],i=0,1,…,2Dh​​−1.

第 iii 对维度使用的角频率定义为：

ωi=b−2iDh,\omega_i = b^{-\frac{2i}{D_h}}, ωi​=b−Dh​2i​,

其中 bbb 是 RoPE Base，通常取 100001000010000。位置 mmm 对应的旋转角度为：

θm,i=mωi.\theta_{m,i}=m\omega_i. θm,i​=mωi​.

二维旋转矩阵为：

R(θm,i)=[cos⁡θm,i−sin⁡θm,isin⁡θm,icos⁡θm,i].R(\theta_{m,i}) = \begin{bmatrix} \cos\theta_{m,i} & -\sin\theta_{m,i}\\ \sin\theta_{m,i} & \cos\theta_{m,i} \end{bmatrix}. R(θm,i​)=[cosθm,i​sinθm,i​​−sinθm,i​cosθm,i​​].

因此旋转后的 Query 为：

[Qm,2i′Qm,2i+1′]=R(θm,i)[Qm,2iQm,2i+1].\begin{bmatrix} Q'_{m,2i}\\ Q'_{m,2i+1} \end{bmatrix} = R(\theta_{m,i}) \begin{bmatrix} Q_{m,2i}\\ Q_{m,2i+1} \end{bmatrix}. [Qm,2i′​Qm,2i+1′​​]=R(θm,i​)[Qm,2i​Qm,2i+1​​].

展开后：

Qm,2i′=Qm,2icos⁡θm,i−Qm,2i+1sin⁡θm,i,Qm,2i+1′=Qm,2isin⁡θm,i+Qm,2i+1cos⁡θm,i.\begin{aligned} Q'_{m,2i} &= Q_{m,2i}\cos\theta_{m,i} - Q_{m,2i+1}\sin\theta_{m,i},\\ Q'_{m,2i+1} &= Q_{m,2i}\sin\theta_{m,i} + Q_{m,2i+1}\cos\theta_{m,i}. \end{aligned} Qm,2i′​Qm,2i+1′​​=Qm,2i​cosθm,i​−Qm,2i+1​sinθm,i​,=Qm,2i​sinθm,i​+Qm,2i+1​cosθm,i​.​

为什么旋转以后包含相对位置？

下面省略 Batch 和 Head 下标，并用 RmR_mRm​ 表示位置 mmm 上所有二维旋转矩阵组成的 Block-diagonal Matrix。

(RmQm)T(RnKn)=QmTRmTRnKn=QmTRn−mKn.\begin{aligned} (R_mQ_m)^T(R_nK_n) &= Q_m^TR_m^TR_nK_n\\ &= Q_m^TR_{n-m}K_n. \end{aligned} (Rm​Qm​)T(Rn​Kn​)​=QmT​RmT​Rn​Kn​=QmT​Rn−m​Kn​.​

因为二维旋转矩阵满足：

RmTRn=Rn−m,R_m^TR_n=R_{n-m}, RmT​Rn​=Rn−m​,

所以旋转后 Query–Key 的点积不仅与内容有关，还与相对位置 n−mn-mn−m 有关。这就是 RoPE 能把相对位置信息注入 Attention Score 的原因。

1.3 Scaled Dot-product Attention

Attention 的输入 Shape 为：

Q,K,V∈RB×H×T×Dh,Q,K,V\in \mathbb R^{B\times H\times T\times D_h}, Q,K,V∈RB×H×T×Dh​,

其中 HHH 是 Attention Heads 数量，Dh=D/HD_h=D/HDh​=D/H 是每个 Head 的维度。

除以 Dh\sqrt{D_h}Dh​​ 是为了防止 Head Dimension 增大时点积幅度过大，导致 Softmax 过早饱和。Causal Mask 则保证 Decoder 只能看到当前位置及其之前的 Tokens。

1.4 Multi-head Self-Attention

Multi-head Attention 的核心手写点是：

  1. 一次线性映射得到 Q,K,VQ,K,VQ,K,V；
  2. 把 Hidden Dimension 拆成多个 Heads；
  3. 每个 Head 独立计算 Attention；
  4. 合并 Heads 并做输出投影。

1.5 SwiGLU Feed-forward Network

SwiGLU 使用一条分支产生内容，另一条分支经过 SiLU 后充当 Gate：

SwiGLU⁡(x)=Wdown[SiLU⁡(Wgatex)⊙(Wupx)].\operatorname{SwiGLU}(x) = W_{\mathrm{down}} \left[ \operatorname{SiLU}(W_{\mathrm{gate}}x) \odot (W_{\mathrm{up}}x) \right]. SwiGLU(x)=Wdown​[SiLU(Wgate​x)⊙(Wup​x)].

1.6 Transformer Block

现代 Decoder-only LLM 通常使用 Pre-Norm：先做 RMSNorm，再进入 Attention/FFN，最后加 Residual。

Residual Connection 为：

x←x+f(Norm⁡(x)),x\leftarrow x+f(\operatorname{Norm}(x)), x←x+f(Norm(x)),

既保留原始信息，也为深层网络提供更直接的梯度传播路径。

二、什么是大模型后训练？

大模型的训练通常可以粗略分为三个阶段：

  1. Pre-training（预训练）：在海量文本上做 Next-token Prediction，学习语言、知识和一定的推理能力。
  2. Supervised Fine-tuning，SFT（监督微调）：使用“指令—回答”数据训练模型，使其学会遵循指令和使用目标输出格式。
  3. Post-training（后训练）：进一步利用偏好、规则或环境反馈优化模型，使其回答更符合人类偏好，或者在数学、代码等任务上取得更高的最终正确率。

大模型 RL 后训练的核心目标是：训练信号不再只是“模仿参考答案中的每个 Token”，而是利用 Reward 直接优化模型自己生成的结果。

SFT 与 RL 的区别可以概括为：

SFT：模仿给定 DemonstrationRL：优化模型自己生成的 Outcome\boxed{ \text{SFT：模仿给定 Demonstration} \qquad \text{RL：优化模型自己生成的 Outcome} } SFT：模仿给定 DemonstrationRL：优化模型自己生成的 Outcome​

同一道数学题可能有多条正确推理路径。SFT 通常提高某一条参考回答的似然，而 RL 可以让模型自行生成不同的 Response，再根据最终答案是否正确给予 Reward。因此，具有可自动验证结果的数学、代码和形式化证明任务尤其适合 RL。

3.2 LLM 生成如何对应强化学习？

一条 Response 的生成可以看作一个有限长度的 Markov Decision Process（MDP）：

  • State：

    st=(x,y<t),s_t=(x,y_{<t}), st​=(x,y<t​),

    即 Prompt 加上已经生成的 Tokens。

  • Action：

    at=yt,a_t=y_t, at​=yt​,

    即选择下一个 Token。

  • Policy：

    πθ(at∣st)=πθ(yt∣x,y<t).\pi_\theta(a_t\mid s_t) = \pi_\theta(y_t\mid x,y_{<t}). πθ​(at​∣st​)=πθ​(yt​∣x,y<t​).

  • State Transition：将新 Token 追加到上下文中：

    st+1=(x,y≤t).s_{t+1}=(x,y_{\le t}). st+1​=(x,y≤t​).

  • Reward：可以是每一步的即时 Reward rtr_trt​，也可以只在完整回答结束时给出 Terminal Reward。

在数学正确性这类 Outcome Reward 中，常见设置是：

r1=⋯=rT−1=0,rT=R(x,y).r_1 =\cdots= r_{T-1}=0, \qquad r_T=R(x,y). r1​=⋯=rT−1​=0,rT​=R(x,y).

这里 R(x,y)R(x,y)R(x,y) 是完整回答的得分，例如答案正确为 111、错误为 000。

3.3 Return、Value、Q Value 与 Advantage

从第 ttt 步开始的折扣累计回报称为 Return：

其中 γ∈[0,1]\gamma\in[0,1]γ∈[0,1] 是 Discount Factor。LLM 的一条 Response 通常是有限长度序列，而且主要关注最终结果，因此实践中经常取 γ\gammaγ 接近或等于 111。

状态价值函数表示：从状态 sts_tst​ 出发，继续按照当前策略生成，预期能获得多少 Return：

Vπ(st)=Eπ[Gt∣st].V^\pi(s_t) = \mathbb E_\pi[G_t\mid s_t]. Vπ(st​)=Eπ​[Gt​∣st​].

四、在线 RL 后训练的完整流程

在线（Online）表示训练数据中的 Response 由当前或最近版本的 Policy 在训练过程中不断生成，而不是完全来自一个固定数据集。

完整 Pipeline 可以表示为：

Prompt Sampling→Policy Rollout→Reward→Advantage→Policy Update→Evaluation\boxed{ \text{Prompt Sampling} \rightarrow \text{Policy Rollout} \rightarrow \text{Reward} \rightarrow \text{Advantage} \rightarrow \text{Policy Update} \rightarrow \text{Evaluation} } Prompt Sampling→Policy Rollout→Reward→Advantage→Policy Update→Evaluation​

4.1 第一步：采样 Prompt

从 Prompt Dataset 中采样一批输入：

x1,x2,…,xB∼Dprompt,x_1,x_2,\ldots,x_B\sim D_{\mathrm{prompt}}, x1​,x2​,…,xB​∼Dprompt​,

其中：

  • DpromptD_{\mathrm{prompt}}Dprompt​ 是 Prompt 的数据分布；
  • BBB 是一个 Rollout Batch 中的 Prompt 数量。

数据可以来自数学、问答、选择题和代码等多个任务。多任务训练时，任务采样比例会直接改变不同任务对总梯度的贡献。

4.2 第二步：Policy Rollout

使用生成当前数据的 Behavior Policy πθold\pi_{\theta_{\mathrm{old}}}πθold​​ 为每个 Prompt 生成回答：

yi∼πθold(⋅∣xi).y_i\sim\pi_{\theta_{\mathrm{old}}}(\cdot\mid x_i). yi​∼πθold​​(⋅∣xi​).

如果每个 Prompt 生成 GGG 条 Response，则记为：

yi,1,yi,2,…,yi,G.y_{i,1},y_{i,2},\ldots,y_{i,G}. yi,1​,yi,2​,…,yi,G​.

Rollout 时需要确定：

  • Sampling Temperature；
  • Top-ppp 或 Top-kkk；
  • 每个 Prompt 的 Rollout 数 GGG；
  • Max Response Length；
  • Stop Tokens。

探索强度太低时，多个 Response 可能几乎完全相同；探索强度太高时，又可能生成大量无意义文本。

4.3 第三步：计算 Reward

每条 Response 得到 Reward：

Ri,j=R(xi,yi,j).R_{i,j}=R(x_i,y_{i,j}). Ri,j​=R(xi​,yi,j​).

常见 Reward 来源包括：

  1. Rule-based / Verifiable Reward：使用答案匹配、单元测试、编译器或定理验证器自动判断；
  2. Reward Model：训练一个模型预测人类更喜欢哪种回答；
  3. AI Feedback：使用更强模型充当 Judge；
  4. Process Reward：对中间推理步骤评分；
  5. Format Reward：检查是否满足规定格式。

从理论上看，Reward Function 是一个将 Prompt 与 Response 映射为标量的函数：

R:X×Y→R,R:\mathcal X\times\mathcal Y\rightarrow\mathbb R, R:X×Y→R,

其中 X\mathcal XX 和 Y\mathcal YY 分别表示 Prompt Space 与 Response Space。R(x,y)R(x,y)R(x,y) 越大，表示回答 yyy 在 Prompt xxx 下越符合优化目标。

例如，对于答案可以自动验证的任务，可以使用二值 Outcome Reward：

R(x,y)=1[extract⁡(y)=a∗],R(x,y) = \mathbf 1[\operatorname{extract}(y)=a^*], R(x,y)=1[extract(y)=a∗],

其中 1[⋅]\mathbf 1[\cdot]1[⋅] 是示性函数，条件成立时为 111，否则为 000；extract⁡(y)\operatorname{extract}(y)extract(y) 表示从回答中提取最终答案；a∗a^*a∗ 是标准答案。

4.4 第四步：估计 Advantage

不同算法主要在这里产生分歧：

  • PPO：训练 Critic 估计 Vϕ(st)V_\phi(s_t)Vϕ​(st​)，再通过 GAE 计算 Token-level Advantage；
  • GRPO / DAPO：不训练 Critic，而是用同一 Prompt 下多个 Response 的相对 Reward 构造 Group-relative Advantage；
  • REINFORCE / RLOO：使用完整 Return，并配合不同形式的 Baseline 降低方差。

其中 ϕ\phiϕ 表示 Critic 的参数，与 Actor 参数 θ\thetaθ 相互独立。

4.5 第五步：更新 Policy

利用 Advantage 更新 Actor。Policy Gradient 的核心直觉是：

At>0⇒提高动作 at 的概率\boxed{ A_t>0\Rightarrow \text{提高动作 }a_t\text{ 的概率} } At​>0⇒提高动作 at​ 的概率​

PPO、GRPO 和 DAPO 都会限制一次更新的幅度，避免新 Policy 相对生成数据的 Old Policy 变化过大。

五、训练中到底有哪些模型？

不同算法需要的模型数量不同。先区分以下角色。

5.1 Actor / Policy Model

Actor 就是实际生成回答并接受更新的语言模型：

πθ(yt∣x,y<t).\pi_\theta(y_t\mid x,y_{<t}). πθ​(yt​∣x,y<t​).

训练完成后，最终部署的一般也是 Actor。

Critic 预测每个 State 的价值：

它通常由 Transformer Backbone 加 Scalar Value Head 构成。Critic 不负责生成 Token，也不是 Reward Model。它的任务只是给 Actor 提供更稳定的 Advantage Baseline。

5.3 Reward Model

Reward Model 接收 Prompt 和完整 Response，输出一个标量分数：

其中 ψ\psiψ 是 Reward Model 的参数。Reward Model 表示回答质量，而 Critic 表示“从当前生成状态继续生成的预期回报”，两者含义不同。

5.4 Old Policy

Old Policy πθold\pi_{\theta_{\mathrm{old}}}πθold​​ 是生成当前 Rollout 数据的 Behavior Policy。PPO 类算法需要比较新旧 Policy：

πθ(at∣st)πθold(at∣st).\frac{\pi_\theta(a_t\mid s_t)} {\pi_{\theta_{\mathrm{old}}}(a_t\mid s_t)}. πθold​​(at​∣st​)πθ​(at​∣st​)​.

实现中不一定长期保存一份独立 Old Model，常见做法是保存 Rollout 时动作的 old_log_probs。

Reference Policy πref\pi_{\mathrm{ref}}πref​ 通常是冻结的 SFT Model，用于约束 Actor 不要偏离初始模型过远：

DKL(πθ∥πref).D_{\mathrm{KL}} (\pi_\theta\Vert\pi_{\mathrm{ref}}). DKL​(πθ​∥πref​).

Reference Policy 与 Old Policy 不是一回事：

  • Old Policy 会随训练迭代更新，用来构造 Importance Ratio；
  • Reference Policy 通常长期冻结，用来提供 KL 锚点；
  • 如果算法没有使用 KL，Reference Policy 可以完全不加载。

六、从 Policy Gradient 开始理解

6.1 最基本的目标

希望最大化模型生成回答的期望 Reward：

利用 Log-derivative Trick，可以得到 REINFORCE 形式的梯度：

∇θJ(θ)=E[R(x,y)∇θlog⁡πθ(y∣x)].\nabla_\theta J(\theta) = \mathbb E \left[ R(x,y) \nabla_\theta\log\pi_\theta(y\mid x) \right]. ∇θ​J(θ)=E[R(x,y)∇θ​logπθ​(y∣x)].

这说明：如果一条回答 Reward 高，就提高其中已采样 Tokens 的概率；如果 Reward 低，就降低这些 Tokens 的概率。

6.2 为什么不直接使用 Reward？

绝对 Reward 没有考虑题目难度。例如两道题分别得到 0.60.60.6：

  • 对简单题而言，模型通常能得到 0.90.90.9，那么 0.60.60.6 其实较差；
  • 对困难题而言，模型通常只能得到 0.10.10.1，那么 0.60.60.6 已经很好。

因此引入 Baseline：

At=Gt−b(st).A_t=G_t-b(s_t). At​=Gt​−b(st​).

只要 Baseline 不依赖当前采样动作，它不会改变 Policy Gradient 的期望，但可以降低方差。PPO 使用 Learned Critic：

6.3 TD Residual 与 GAE

从 Bellman 关系理解 TD Residual

对于当前策略 π\piπ，真实状态价值满足 Bellman Expectation Equation：

Vπ(st)=Eπ[rt+γVπ(st+1)∣st].V^\pi(s_t) = \mathbb E_\pi \left[ r_t+\gamma V^\pi(s_{t+1}) \mid s_t \right]. Vπ(st​)=Eπ​[rt​+γVπ(st+1​)∣st​].

也就是说，一个 State 的价值应等于“执行下一步后获得的即时 Reward”与“下一个 State 的折扣价值”之和的期望。

实际训练中并不知道真实的 VπV^\piVπ，只能让 Critic VϕV_\phiVϕ​ 对它进行近似。对于一次真实采样到的 Transition：

(st,at,rt,st+1),(s_t,a_t,r_t,s_{t+1}), (st​,at​,rt​,st+1​),

作为 Vϕ(st)V_\phi(s_t)Vϕ​(st​) 的一步 Bootstrap Target。这里的 Bootstrap 指：目标中使用了模型自身对下一个 State 的 Value 估计，而不是必须等到整条轨迹结束后再计算完整 Return。

两者之差称为 Temporal Difference Residual（TD 残差）：

δt=rt+γVϕ(st+1)−Vϕ(st).\delta_t = r_t +\gamma V_\phi(s_{t+1}) -V_\phi(s_t). δt​=rt​+γVϕ​(st+1​)−Vϕ​(st​).

其中：

  • sts_tst​：生成第 ttt 个 Token 前的 State；
  • ata_tat​：在 sts_tst​ 下选择的 Token；
  • rtr_trt​：执行 ata_tat​ 后得到的即时 Reward；
  • st+1s_{t+1}st+1​：追加该 Token 后的新 State；
  • Vϕ(st)V_\phi(s_t)Vϕ​(st​)：Critic 对当前 State Value 的估计；
  • γ\gammaγ：Discount Factor。

TD Residual 可以理解为一次 Transition 带来的“超出预期程度”：

  • δt>0\delta_t>0δt​>0：实际得到的“即时 Reward + 下一状态价值”高于 Critic 原本对 sts_tst​ 的估计；
  • δt<0\delta_t<0δt​<0：这一步之后的结果低于预期；
  • 如果 Critic 已经准确，在给定 sts_tst​ 的条件下，δt\delta_tδt​ 的期望应接近 000。

但只用：

A^t=δt\hat A_t=\delta_t A^t​=δt​

估计 Advantage 时，只显式观察一步 Transition，虽然方差较低，却会比较依赖 Critic 对 Vϕ(st+1)V_\phi(s_{t+1})Vϕ​(st+1​) 的估计。另一方面，如果直接使用完整 Monte Carlo Return：

A^t=Gt−Vϕ(st),\hat A_t=G_t-V_\phi(s_t), A^t​=Gt​−Vϕ​(st​),

就能利用整条轨迹的真实 Reward，但长序列上的方差通常更大，导致梯度估计更容易受单次采样结果影响、训练波动更明显，并且需要更多样本取平均。GAE 的目的就是在这两个极端之间进行折中。

GAE 的定义

Generalized Advantage Estimation（GAE）将当前及未来的 TD Residual 加权求和：

A^tGAE=∑l=0T−t(γλ)lδt+l,\hat A_t^{\mathrm{GAE}} = \sum_{l=0}^{T-t} (\gamma\lambda)^l\delta_{t+l}, A^tGAE​=l=0∑T−t​(γλ)lδt+l​,

将前几项展开：

A^tGAE=δt+γλδt+1+(γλ)2δt+2+⋯ .\hat A_t^{\mathrm{GAE}} = \delta_t +\gamma\lambda\delta_{t+1} +(\gamma\lambda)^2\delta_{t+2} +\cdots. A^tGAE​=δt​+γλδt+1​+(γλ)2δt+2​+⋯.

其中：

  • lll：从当前时间步向后移动的步数；
  • γ∈[0,1]\gamma\in[0,1]γ∈[0,1]：控制未来 Reward 的折扣；
  • λ∈[0,1]\lambda\in[0,1]λ∈[0,1]：控制未来 TD Residual 参与当前 Advantage 的程度；
  • TTT：Response 的最后一个生成时间步。

实际实现通常从序列末尾向前递推：

A^t=δt+γλA^t+1.\hat A_t = \delta_t +\gamma\lambda\hat A_{t+1}. A^t​=δt​+γλA^t+1​.

对于 Episode 结束后的 Terminal State，规定：

Vϕ(sT+1)=0,A^T+1=0.V_\phi(s_{T+1})=0, \qquad \hat A_{T+1}=0. Vϕ​(sT+1​)=0,A^T+1​=0.

因此可以先算最后一个 Token 的 A^T\hat A_TA^T​，再依次计算 A^T−1,…,A^1\hat A_{T-1},\ldots,\hat A_1A^T−1​,…,A^1​，时间复杂度为 O(T)O(T)O(T)，不需要对每个位置重复计算后续和。

λ\lambdaλ 如何控制 Bias-Variance Trade-off？

  • 当 λ=0\lambda=0λ=0 时：

    A^t=δt.\hat A_t=\delta_t. A^t​=δt​.

    此时只使用一步 TD 信息，方差较低，但高度依赖 Critic 的 Bootstrap 估计，因此 Bias 可能较大。

  • 当 λ\lambdaλ 接近 111 时：

    A^t≈δt+γδt+1+γ2δt+2+⋯ .\hat A_t \approx \delta_t+\gamma\delta_{t+1} +\gamma^2\delta_{t+2}+\cdots. A^t​≈δt​+γδt+1​+γ2δt+2​+⋯.

    在完整 Episode 且 Terminal State Value 为 000 时，中间的 Value 项会发生 Telescope Cancellation，最终近似：

    A^t≈Gt−Vϕ(st).\hat A_t \approx G_t-V_\phi(s_t). A^t​≈Gt​−Vϕ​(st​).

    此时更接近 Monte Carlo Advantage，Bias 较小，但会引入更多未来随机性，方差通常更大。

因此，GAE 可以理解为对不同长度的 nnn-step Advantage Estimator 进行指数加权：较小的 λ\lambdaλ 更相信短期 Bootstrap，较大的 λ\lambdaλ 更相信完整轨迹的实际结果。

Terminal Reward 如何向前传递？

LLM Reasoning 常只有最终 Outcome Reward：

r1=⋯=rT−1=0,rT=R(x,y).r_1=\cdots=r_{T-1}=0, \qquad r_T=R(x,y). r1​=⋯=rT−1​=0,rT​=R(x,y).

为了看清传播过程，暂时假设 Critic 在所有位置的初始预测都是 000，并取 γ=1\gamma=1γ=1。此时：

δT=R(x,y),δ1=⋯=δT−1=0.\delta_T=R(x,y), \qquad \delta_1=\cdots=\delta_{T-1}=0. δT​=R(x,y),δ1​=⋯=δT−1​=0.

通过 GAE 递推：

A^t=λT−tR(x,y).\hat A_t = \lambda^{T-t}R(x,y). A^t​=λT−tR(x,y).

因此，最终 Reward 可以沿着 Response 从后向前影响更早的 Tokens；距离结尾越远，信号会经过越多次 λ\lambdaλ 衰减。实际训练中 Critic 不为零，每一步的 Advantage 还会受到相邻 State Value 差异的影响。

这解释了 GAE 如何完成数值上的 Credit Assignment，但它并没有获得每一步推理是否正确的直接标签。只有 Terminal Reward 时，PPO 仍然无法真正识别“具体哪一个推理步骤正确或错误”；要获得这种监督，需要 Process Reward 或中间步骤验证器。

Value Target

得到 Advantage 后，Critic 的回归目标可以写成：

G^t=A^t+Vϕ(st).\hat G_t = \hat A_t+V_\phi(s_t). G^t​=A^t​+Vϕ​(st​).

这里 G^t\hat G_tG^t​ 是由 GAE 构造的 Value Target。在更新 Critic 时，右侧用于构造 Target 的数值会停止梯度传播，然后最小化：

Lvalue(ϕ)=Et[(Vϕ(st)−G^t)2].L_{\mathrm{value}}(\phi) = \mathbb E_t \left[ \left( V_\phi(s_t)-\hat G_t \right)^2 \right]. Lvalue​(ϕ)=Et​[(Vϕ​(st​)−G^t​)2].

Actor 使用 A^t\hat A_tA^t​ 判断已采样 Token 应该被提高还是降低概率；Critic 则使用 G^t\hat G_tG^t​ 学习更准确的 Value Baseline。二者使用同一批 Rollout，但优化目标和参数彼此不同。

七、PPO：使用 Critic 的稳定 On-policy 更新

PPO（Proximal Policy Optimization）的核心是：利用当前 Rollout 学习，但限制新 Policy 一次不要偏离生成这些数据的 Old Policy 太远。

7.1 Importance Ratio

Rollout 完成后，每个已采样动作都有一个固定的 Advantage A^t\hat A_tA^t​：

  • A^t>0\hat A_t>0A^t​>0：这个动作比预期好，应提高它的概率；
  • A^t<0\hat A_t<0A^t​<0：这个动作比预期差，应降低它的概率。

Advantage 只负责评价动作好坏，本身不包含待更新参数 θ\thetaθ。要更新 Policy，需要让动作的概率参与目标。对于一个状态 sss，希望最大化 Current Policy 下的期望 Advantage：

Js(θ)=∑aπθ(a∣s)A^old(s,a).J_s(\theta) = \sum_a \pi_\theta(a\mid s) \hat A^{\mathrm{old}}(s,a). Js​(θ)=a∑​πθ​(a∣s)A^old(s,a).

这个式子就是“动作被 Current Policy 选中的概率 × 动作的好坏”。最大化它时，正 Advantage 动作的概率会提高，负 Advantage 动作的概率会降低。

但现有样本不是由 Current Policy 生成的，而是来自 Old Policy。为了使用这批旧样本，将上式改写为：

∑aπθ(a∣s)A^old(s,a)=∑aπθold(a∣s)πθ(a∣s)πθold(a∣s)A^old(s,a).\sum_a\pi_\theta(a\mid s)\hat A^{\mathrm{old}}(s,a) = \sum_a\pi_{\theta_{\mathrm{old}}}(a\mid s) \frac{\pi_\theta(a\mid s)} {\pi_{\theta_{\mathrm{old}}}(a\mid s)} \hat A^{\mathrm{old}}(s,a). a∑​πθ​(a∣s)A^old(s,a)=a∑​πθold​​(a∣s)πθold​​(a∣s)πθ​(a∣s)​A^old(s,a).

因此定义概率比：

ρt(θ)=πθ(at∣st)πθold(at∣st).\rho_t(\theta) = \frac{ \pi_\theta(a_t\mid s_t) }{ \pi_{\theta_{\mathrm{old}}}(a_t\mid s_t) }. ρt​(θ)=πθold​​(at​∣st​)πθ​(at​∣st​)​.

于是可以使用 Old Policy 的样本估计 Current Policy 的目标：

Jsurrogate(θ)=E(st,at)∼πθold[ρt(θ)A^t].J_{\mathrm{surrogate}}(\theta) = \mathbb E_{(s_t,a_t)\sim\pi_{\theta_{\mathrm{old}}}} \left[ \rho_t(\theta)\hat A_t \right]. Jsurrogate​(θ)=E(st​,at​)∼πθold​​​[ρt​(θ)A^t​].

这里 ρt\rho_tρt​ 与 A^t\hat A_tA^t​ 的关系很简单：

  • ρt=1\rho_t=1ρt​=1：新旧 Policy 给该 Token 的概率相同；

  • ρt>1\rho_t>1ρt​>1：新 Policy 提高了该 Token 的概率；

  • ρt<1\rho_t<1ρt​<1：新 Policy 降低了该 Token 的概率。

  • 当 A^t>0\hat A_t>0A^t​>0 时，最大化 ρtA^t\rho_t\hat A_tρt​A^t​ 会推动 ρt\rho_tρt​ 增大，也就是提高该 Token 的概率；

  • 当 A^t<0\hat A_t<0A^t​<0 时，ρtA^t\rho_t\hat A_tρt​A^t​ 是负数。减小 ρt\rho_tρt​ 会让它更接近 000、从而使目标变大，也就是降低该 Token 的概率。

所以 ρtA^t\rho_t\hat A_tρt​A^t​ 不是“概率已经提高后，再把更新幅度放大”，而是把 Current Policy 对该动作的相对概率与动作好坏结合起来，形成一个可以对 θ\thetaθ 优化的目标。

7.2 PPO Clipped Objective

问题是，如果一直最大化 ρtA^t\rho_t\hat A_tρt​A^t​：

  • 正 Advantage 会持续推动 ρt\rho_tρt​ 增大；
  • 负 Advantage 会持续推动 ρt\rho_tρt​ 减小。

而 A^t\hat A_tA^t​ 只是根据一批 Old Policy Rollout 得到的估计，可能有噪声。不能因为一次判断就把 Token 概率改得过多，所以 PPO 只允许这批数据推动 Policy 变化一小段范围。

PPO 的目标为：

JPPO(θ)=Et[min⁡(ρt(θ)A^t, clip⁡(ρt(θ),1−ϵ,1+ϵ)A^t)].J_{\mathrm{PPO}}(\theta) = \mathbb E_t \left[ \min \left( \rho_t(\theta)\hat A_t,\, \operatorname{clip} (\rho_t(\theta),1-\epsilon,1+\epsilon)\hat A_t \right) \right]. JPPO​(θ)=Et​[min(ρt​(θ)A^t​,clip(ρt​(θ),1−ϵ,1+ϵ)A^t​)].

其中：

  • ϵ>0\epsilon>0ϵ>0 控制允许的相对概率变化范围；
  • clip⁡(ρt,1−ϵ,1+ϵ)\operatorname{clip}(\rho_t,1-\epsilon,1+\epsilon)clip(ρt​,1−ϵ,1+ϵ) 将 ρt\rho_tρt​ 截到该区间内；
  • min 在未裁剪项和裁剪项中选择更小、更保守的一个。

现在重新理解“提高到 Old Policy 的 1+ϵ1+\epsilon1+ϵ 倍”。因为：

πθ(at∣st)=ρt πθold(at∣st),\pi_\theta(a_t\mid s_t) = \rho_t\, \pi_{\theta_{\mathrm{old}}}(a_t\mid s_t), πθ​(at​∣st​)=ρt​πθold​​(at​∣st​),

所以 ρt=1+ϵ\rho_t=1+\epsilonρt​=1+ϵ 表示：在当前这轮参数更新中，该 Token 的概率已经变成旧概率的 1+ϵ1+\epsilon1+ϵ 倍。

  • 若 A^t>0\hat A_t>0A^t​>0，提高概率是正确方向；但当 ρt>1+ϵ\rho_t>1+\epsilonρt​>1+ϵ 后，裁剪项保持不变，这个样本不再奖励继续提高概率；
  • 若 A^t<0\hat A_t<0A^t​<0，降低概率是正确方向；但当 ρt<1−ϵ\rho_t<1-\epsilonρt​<1−ϵ 后，裁剪项保持不变，这个样本不再奖励继续降低概率。

注意，这不是把概率硬性锁在边界上，而只是让当前样本在越过边界后不再提供更多收益。

min 用来处理错误方向。PPO 在最大化目标，因此取较小值意味着：

  • 如果 Policy 朝正确方向走得过远，选择裁剪项，停止额外奖励；
  • 如果 Policy 朝错误方向变化，选择更差的未裁剪项，仍然保留纠正它的梯度。

因此，PPO Clipping 的作用可以概括为：限制一次更新从旧 Rollout 中获得的收益，但不掩盖错误方向带来的损失。

7.3 Critic Loss

Critic 回归 Value Target：

Lvalue(ϕ)=Et[(Vϕ(st)−G^t)2].L_{\mathrm{value}}(\phi) = \mathbb E_t \left[ \left( V_\phi(s_t)-\hat G_t \right)^2 \right]. Lvalue​(ϕ)=Et​[(Vϕ​(st​)−G^t​)2].

7.4 Entropy Bonus 与 KL

Policy Entropy 为：

H(πθ(⋅∣st))=−∑a∈Vπθ(a∣st)log⁡πθ(a∣st).\mathcal H(\pi_\theta(\cdot\mid s_t)) = - \sum_{a\in\mathcal V} \pi_\theta(a\mid s_t) \log\pi_\theta(a\mid s_t). H(πθ​(⋅∣st​))=−a∈V∑​πθ​(a∣st​)logπθ​(a∣st​).

Entropy 高表示分布更分散、探索更强；Entropy 过低可能发生 Entropy Collapse，模型过早变得确定。

7.7 PPO 的优势与局限

优势：

  • Learned Critic 可以跨 Prompt 和跨样本学习 Value Baseline；
  • GAE 能提供随 Token/State 变化的 Advantage；
  • Clipping 能控制更新幅度，工程上相对稳定；
  • 同一批 Rollout 可以通过 Mini Batch 和多个 PPO Epoch 重复利用。

局限：

  • 需要额外训练 Critic，显存和计算成本较高；
  • Actor、Critic、Old Log Prob、Reference Model 之间的数据流复杂；
  • Critic 训练不好时，Advantage 估计反而可能产生偏差；
  • On-policy 数据很快过期，不能无限重复使用旧 Rollout；
  • Rollout 往往比梯度更新更耗时。

8.5 GRPO 的优势

  • 不需要训练 Critic，减少模型状态、Value Forward 和 Value Update 的开销；
  • 同一 Prompt 内做相对比较，能一定程度上抵消题目难度差异；
  • 很适合具有可验证 Outcome Reward 的数学和代码任务；
  • Pipeline 比 PPO 更简单。

8.6 GRPO 的问题

全对或全错时没有有效信号

如果：

R1=R2=⋯=RG,R_1=R_2=\cdots=R_G, R1​=R2​=⋯=RG​,

则：

Ri−Rˉ=0⇒A^i=0.R_i-\bar R=0 \quad\Rightarrow\quad \hat A_i=0. Ri​−Rˉ=0⇒A^i​=0.

简单题全部正确、难题全部错误时，这一组 Rollout 几乎不产生 Policy Gradient。

Group Size 有限导致 Baseline 噪声

GGG 较小时，Rˉ\bar RRˉ 和 σR\sigma_RσR​ 只是基于少量样本的局部估计。多任务、难度跨度较大的数据中，Group Baseline 可能具有较高方差。

Rollout 成本增加

为了得到组内比较，每个 Prompt 必须生成多条 Response。Critic 成本下降了，但生成成本增加了。

Response-level Advantage 不等于过程监督

同一 Response 内所有 Tokens 常共享一个 Advantage。模型知道整条回答相对较好或较差，但不知道具体哪一步推理正确。

十、veRL：大模型 RL 后训练框架

10.1 veRL 解决什么问题？

veRL（Volcano Engine Reinforcement Learning）是面向大模型 RL 后训练的分布式训练框架，也是 HybridFlow 的开源实现。PPO、GRPO 和 DAPO 回答的是“模型应该怎样更新”，veRL 回答的则是“如何让这套算法在多机多卡上真正运行起来”。

一次在线 RL 训练不只有 Forward 和 Backward，还需要反复执行：

这条链涉及多种模型和计算引擎：

  • Actor 负责训练，需要保存 Gradient 和 Optimizer State；
  • Rollout Engine 负责生成，需要 KV Cache 和高吞吐推理；
  • PPO 还需要 Critic 计算 Value；
  • KL 正则可能需要冻结的 Reference Policy；
  • Reward 可能来自规则、代码执行器或 Reward Model。

它们使用的并行方式、显存和执行时机都不相同。veRL 的作用，就是把这些角色组织成一条完整的数据流，并管理分布式执行、GPU 分配、Batch 传递以及 Actor 到 Rollout Engine 的权重同步。

veRL 也提供 SFT 等能力，但其核心优势仍然是 PPO、GRPO 等包含在线 Rollout 的 RL 训练。

10.2 先看 veRL 的整体运行结构

理解 veRL 时，可以先只记住三层：

第一层：Trainer / Driver 决定执行顺序

RayPPOTrainer 通常运行在 Driver Process 中。它维护 PPO 的全局控制流，决定什么时候生成、什么时候计算 Reward、什么时候更新 Critic 和 Actor。

Driver 本身不执行大模型的分布式 Forward 或 Backward。它更像调度者：准备 Batch，调用对应角色，接收结果，再把结果交给下一阶段。

第二层：Worker / WorkerGroup 执行某个模型角色

Actor、Rollout、Critic 等角色由远程 Workers 执行。多个共同运行一个分布式模型的 Workers 组成一个 WorkerGroup。

第三层：Engine / Backend 完成真正的模型计算

Worker 内部再调用具体计算引擎：

  • Actor/Critic Training 可以使用 FSDP、FSDP2 或 Megatron；
  • Rollout Generation 可以使用 vLLM 或 SGLang。

10.3 把算法角色映射到 GPU

上一节说明了程序由 Trainer 调用 WorkerGroup。接下来还要解决两个问题：需要创建哪些 WorkerGroup，以及它们分别放在哪些 GPU 上。

Role：需要哪些计算角色？

Role 是算法中的逻辑角色：

  • ActorRollout：训练 Policy，并使用 Policy 生成 Response；
  • Critic：PPO 中的 Value Model；
  • RefPolicy：计算 KL 时使用的冻结 Reference Policy；
  • RewardModel：使用模型打分时的 Reward Model。

不是每次训练都需要全部角色。例如 PPO 需要 Actor/Rollout 和 Critic，但 Reference Policy、Reward Model 都是可选的；GRPO 一般不需要 Critic。

veRL 会根据配置把这些 Role 映射为相应的 WorkerGroup。理解时重点关注每个角色的输入和输出，不需要死记具体的 Worker Class 名称。

ResourcePool：这些角色放在哪些 GPU 上？

ResourcePool 表示一组可供 Worker 使用的 GPU。Role 到 ResourcePool 的 Mapping 决定每个角色部署在哪里。

如果多个角色映射到同一个 ResourcePool，它们会共享同一批 GPU，并在不同训练阶段分时运行，这称为 Colocation。例如 Rollout 结束后释放或休眠 KV Cache，再使用这些 GPU 更新 Actor。

如果给 Rollout 和 Training 分配不同 Resource Pools，则两者可以独立运行，减少显存切换和资源竞争，但需要更多 GPU，也要承担跨资源池同步权重的开销。

DataProto：阶段之间传递什么？

不同 WorkerGroup 之间不直接传递零散变量，而是通过统一的 DataProto 传递一个 Batch。它包含：

  • Tensor Batch：input_ids、responses、old_log_probs 等；
  • Non-tensor Batch：原始文本、数据来源、Ground Truth 等；
  • Meta Info：动态 Batch、Timing 等控制信息。

可以把 DataProto 理解成贯穿一次 RL Iteration 的数据包：Rollout 向其中加入 Response，Critic 加入 Value，Reward Function 加入 Reward，Advantage Estimator 再加入 Advantage 和 Return。后面的 PPO 流程会具体说明这些字段怎样逐步产生。

10.4 从启动脚本到训练循环

运行一个 veRL PPO 脚本时，程序首先完成初始化：

  1. 读取 Hydra 配置，确定模型、数据、算法和集群参数；
  2. 启动 Ray，获得当前节点上的 GPU 资源；
  3. 加载 Dataset、Tokenizer 和 Reward Function；
  4. 根据配置确定需要 Actor/Rollout、Critic、Reference、Reward Model 中的哪些角色；
  5. 将这些 Role 映射到 ResourcePool，并初始化对应的 WorkerGroup；
  6. 构造 RayPPOTrainer，调用 fit() 进入训练循环。

这部分只是在“搭建舞台”。真正的数据流发生在 RayPPOTrainer.fit() 中：它每次从 DataLoader 取得一批 Prompt，让各个 WorkerGroup 按照 PPO 顺序处理这批数据。

10.5 一次 PPO 在 veRL 中如何执行？

这一节只跟踪一批 Prompt，重点看每一步由谁执行、返回什么，以及结果怎样交给下一步。

第一步：取出 Prompt

DataLoader 从训练集中取出一批样本。每条样本主要包含两部分：

  • 给模型的问题，例如一道数学题或一段用户指令；
  • 计算 Reward 所需的信息，例如标准答案、测试用例或任务类型。

Tokenizer 将文本 Prompt 转换成 Token IDs，并通过 Padding 把同一 Batch 补到相同长度。最终得到的不是新的训练结果，只是一批已经整理好、可以送入模型生成的 Prompt。

第二步：生成 Response

Rollout Worker 接收上一阶段整理好的 Prompt，使用当前 Policy 生成答案。底层通常由 vLLM 或 SGLang 执行高吞吐推理。

如果每个 Prompt 采样 GGG 次，就会得到 GGG 条不同的 Response。每个“Prompt + Response”组成一条完整轨迹。

这一步的主要输出就是一批模型答案，同时还会记录每条答案的有效长度，避免后续把补齐长度使用的 Padding 当成模型真正生成的内容。

第三步：计算 Reward

Trainer 将每条 Prompt、生成的 Response 和标准答案等验证信息交给 Reward Function 或 Reward Model。

例如，数学题可以检查最终答案，代码题可以运行测试用例，主观问答可以由 Reward Model 打分。这一步通常为每条完整 Response 返回一个标量，表示这条答案整体有多好。

为了与后续按 Token 计算的 GAE 对齐，veRL 会把这个分数放在 Response 的最后一个有效 Token 上。如果启用了 KL Reward，还会减去 Actor 偏离 Reference Policy 的惩罚。

第四步：确定这批数据的 Old Log Probability

这批 Response 是由更新前的 Policy 生成的。为了进行 PPO 更新，需要知道旧策略当时认为每个已生成 Token 有多大概率。

Training Actor 会重新读取固定的 Prompt–Response，不再生成新答案，而是一次性计算旧策略赋予每个 Response Token 的 Log Probability，这就是 Teacher-forcing Forward。

之所以由 Training Actor 重新计算，而不直接使用 Rollout Engine 返回的概率，是因为生成与训练可能分别使用 vLLM/SGLang 和 FSDP/Megatron。重新计算可以让 Old Log Probability 与后面 Current Log Probability 使用一致的模型计算路径，减少不同引擎造成的数值偏差。

这些旧概率在整轮 PPO 更新中保持不变，后面会与更新中的 Current Actor 概率比较，计算 Importance Ratio。

第五步：补齐 PPO 所需的其他量

如果启用了 KL，Reference Policy 会读取同一批 Prompt–Response，计算自己赋予每个 Response Token 的概率。将它与 Actor 的概率比较，就能衡量 Actor 偏离 Reference Policy 的程度。

Critic 也会读取这些完整轨迹。与 Actor 预测“下一个 Token 是什么”不同，Critic 为每个生成位置预测“从这里继续生成，最终预计能得到多少回报”，也就是 Value。

至此，每条轨迹已经有了实际 Reward、旧策略概率和 Critic 对未来回报的预测。

第六步：计算 Advantage 与 Return

Trainer 将实际 Reward 与 Critic 预测的 Value 交给 GAE，产生两种训练信号：

  • Advantage：这次实际生成相对于 Critic 原本预期好多少，用于训练 Actor；
  • Return：Critic 后续应该拟合的目标，用于训练 Critic。

简单来说，这一步把“模型最终得了多少分”转换成 Actor 和 Critic 各自可以直接学习的目标。具体计算公式对应前文的 GAE。

第七步：先更新 Critic

Trainer 把完整轨迹和刚刚算出的 Return 交给 Critic WorkerGroup。

Critic 重新预测每个生成位置的 Value，并与 Return 比较，计算 Value Loss，然后反向传播更新 Critic。这个阶段只让 Critic 的估值更加准确，不会直接改变 Actor 的生成概率。

第八步：再更新 Actor

Trainer 再把固定轨迹、旧策略概率和 Advantage 交给 Actor WorkerGroup。Actor 会：

  1. 重新计算 Current Actor 对这些 Response Tokens 的概率；
  2. 与生成数据时的旧策略概率比较，构造 Importance Ratio；
  3. 结合 Advantage 计算 PPO Clipped Objective；
  4. 执行 Backward 和 Optimizer Step。

这里不会重新生成 Response，而是在同一批固定 Tokens 上更新 Actor。

同一批 Rollout 可以重复训练多轮，但作为比较基准的旧策略概率始终不变。

第九步：同步新权重，开始下一轮

Actor 更新后，新权重需要进入 Rollout Engine。下一批 Prompt 必须由更新后的 Policy 生成，否则 Rollout Policy 会一直停留在旧版本。

veRL 将更新后的 Actor 权重同步给 Rollout Engine。Trainer 随后记录 Reward、KL、Clip Fraction、Value Loss 和各阶段耗时，并按配置执行 Validation 或保存 Checkpoint，再读取下一批 Prompt。

Training Backend

10.9 显存与性能调优

定位性能问题时，应先区分发生在哪个阶段。

Rollout OOM 或吞吐低

重点检查：

  • max_prompt_length 与 max_response_length；
  • rollout.n；
  • tensor_model_parallel_size；
  • gpu_memory_utilization；
  • max_num_batched_tokens；
  • max_num_seqs；
  • KV Cache 是否在角色切换时正确释放或休眠。

Actor/Critic Update OOM

重点检查：

  • PPO Micro Batch；
  • Dynamic Batch 的 Max Tokens per GPU；
  • Gradient Checkpointing；
  • Remove Padding；
  • FSDP Parameter/Optimizer Offload；
  • Sequence Parallel Size；
  • Model、Gradient、Optimizer State 与 Activation 的显存占用。

GPU 利用率低

常见原因包括：

  • Response 长度差异导致 Straggler；
  • Micro Batch 太小；
  • Rollout TP 太大、Replica 太少；
  • 生成阶段 max_num_batched_tokens 太低；
  • Worker 之间存在同步等待；
  • Reward Function 或外部 Sandbox 成为 CPU/Network Bottleneck。

veRL 的 Timing Metrics 会将 gen、reward、old_log_prob、values、adv、update_actor 和 update_critic 分开记录，应先找到耗时最大的阶段，再调整对应配置。

  • 当前 OOM 或性能瓶颈属于 Rollout、Forward 还是 Backward？

十一、PPO、GRPO、DAPO 的关系

11.1 PPO 与 GRPO

两者都使用：

  • Online Rollout；
  • Importance Ratio；
  • Clipped Policy Objective；
  • Reward 驱动的策略更新。

主要区别是 Advantage Baseline：

PPO：Critic + GAE\boxed{ \text{PPO：Critic + GAE} } PPO：Critic + GAE​

GRPO：同 Prompt 多 Response 的组内相对 Reward\boxed{ \text{GRPO：同 Prompt 多 Response 的组内相对 Reward} } GRPO：同 Prompt 多 Response 的组内相对 Reward​

PPO 节省同 Prompt 的多次采样，但需要训练 Critic；GRPO 去掉 Critic，但依赖多个 Rollout 形成可靠的 Group Baseline。

11.2 GRPO 与 DAPO

DAPO 继承了 GRPO 的 Group-relative Advantage，但针对 Long-CoT 做了系统改进：

  • 对称 Clip 改成 Clip-Higher；
  • 随机 Prompt Batch 改成过滤零方差 Group 的 Dynamic Sampling；
  • Sample-level Loss 改成 Token-level Loss；
  • 对硬截断改成平滑的 Overlong Reward Shaping；
  • 原始 DAPO Recipe 移除了 KL。

因此 DAPO 不是完全不同的理论框架，更像是围绕 GRPO-style RL 构建的一套大规模 Reasoning RL Recipe。

十二、实践中最容易忽略的问题

12.1 Reward Hacking

Policy 优化的是给定 Reward，而不是开发者心中真正想要的能力。如果 Reward Function 存在漏洞，模型可能学会钻漏洞。

例如只检查最终答案字符串时，模型可能碰巧输出正确答案，但推理过程完全错误。解决思路包括：

  • 改进答案解析和等价性判断；
  • 使用隐藏测试用例；
  • 同时检查格式、过程与最终结果；
  • 定期人工审查高 Reward 样本；
  • 在训练外使用独立 Evaluation。

12.2 Sparse Reward

如果困难题几乎全部得到 000：

P(R>0)≈0,P(R>0)\approx0, P(R>0)≈0,

就没有足够的正向信号。可以使用：

  • SFT Cold Start；
  • Curriculum Learning；
  • 增加每个 Prompt 的 Rollout 数；
  • Process / Partial Reward；
  • 将任务分解成更容易的子任务。

12.3 Entropy Collapse

Policy 过早变得确定时，多条 Rollout 几乎一致，探索能力下降。应监控：

H(πθ),\mathcal H(\pi_\theta), H(πθ​),

并结合 Sampling Temperature、Entropy Bonus、Clip Range 和 DAPO Clip-Higher 调整。

Entropy 也不是越大越好。过高可能表示输出随机、无法收敛；目标是在探索与利用之间取得平衡。

12.4 长度偏差与截断

长 Response 会带来：

  • 更高 Rollout 延迟；
  • 更大的 KV Cache；
  • 更多训练激活值；
  • 更高的截断概率；
  • Sample-level 与 Token-level Loss 权重差异。

因此应同时监控：

  • Mean Response Length；
  • Max-length Hit Rate；
  • Truncation Rate；
  • 正确与错误样本各自的长度分布；
  • Reward 与长度的相关性。

12.5 Prompt 分布偏移

训练与最终评测的 Prompt Template 不一致时，表现可能下降。变化可能来自：

  • System Prompt；
  • 是否要求输出推理过程；
  • 最终答案格式；
  • Few-shot Examples；
  • 中英文指令；
  • Stop Tokens 与 Chat Template。

稳妥做法是让训练 Prompt 覆盖可能的评测格式，并单独做 Prompt Robustness Evaluation，而不是只在单一 Template 上报告结果。

12.6 多任务 Mixture 与 Task Interference

多任务目标可写为：

J(θ)=∑k=1KwkJk(θ),J(\theta) = \sum_{k=1}^{K} w_kJ_k(\theta), J(θ)=k=1∑K​wk​Jk​(θ),

其中：

  • KKK：任务数量；
  • JkJ_kJk​：第 kkk 个任务的目标；
  • wkw_kwk​：该任务在总目标中的权重。

改变采样比例，本质上会改变各任务对总梯度的贡献。比例选择不应只看哪个任务当前 Reward 最低，而应看：

  • 各任务独立 Held-out Validation；
  • Reward / Accuracy 的改善趋势；
  • 是否已经 Plateau；
  • 增加训练预算后的边际收益；
  • 是否存在一个任务提升、另一个任务持续退化。

如果两个任务梯度满足：

说明它们的更新方向存在冲突，可能出现 Task Interference。这时除了调 Mixture，还可以考虑更小的 Learning Rate、分阶段训练或 Multi-task Gradient Balancing。

12.7 Online RL 的 Off-policy 程度

Rollout 来自 πθold\pi_{\theta_{\mathrm{old}}}πθold​​，更新的是 πθ\pi_\thetaπθ​。如果同一批数据训练太多轮，新旧 Policy 差距会越来越大：

πθ≉πθold.\pi_\theta \not\approx \pi_{\theta_{\mathrm{old}}}. πθ​≈πθold​​.

Importance Sampling 的方差增大，大量 Tokens 会被 Clip。因此应结合：

  • PPO Epochs；
  • Learning Rate；
  • Clip Fraction；
  • Approximate KL；
  • Rollout 更新频率；

判断是否过度重复使用旧数据。

十三、总结

理解大模型 RL 后训练，可以抓住两条主线。

第一条是统一 Pipeline：

Prompt→Rollout→Reward→Advantage→Policy Update.\text{Prompt} \rightarrow \text{Rollout} \rightarrow \text{Reward} \rightarrow \text{Advantage} \rightarrow \text{Policy Update}. Prompt→Rollout→Reward→Advantage→Policy Update.

第二条是不同算法如何构造 Advantage 并稳定更新 Policy：

PPO：CriticGRPO / DAPO：Group Reward\text{PPO：Critic} \qquad \text{GRPO / DAPO：Group Reward} PPO：CriticGRPO / DAPO：Group Reward

PPO 通过 Critic 与 GAE 提供较稳定的 Advantage，但需要额外训练 Value Model；GRPO 用同一 Prompt 下的组内 Reward 比较删除 Critic，但依赖多次 Rollout 和有效的组内 Reward 方差；DAPO 则进一步针对 Long-CoT 中的探索、有效采样、Loss 聚合和截断问题改进 GRPO-style Training。

最终选择哪种方法，取决于 Reward 是否可验证、Rollout 预算、显存限制、任务难度以及 Critic 能否提供可靠的 Value Estimation。
